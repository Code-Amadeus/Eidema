# Eidema：热、温、冷路径与人格的交互关系

日期：2026-10-23（Pacific/Auckland）。

状态：记录用户提出的设计方向，尚未定论。当前设计暂留在初稿，待用户进一步梳理后继续讨论；本文不冻结组件、字段、接口、模型调用或资源参数，不开始实现。

## 1. 需要补足的视角

Eidema 的目标包含交互中的记忆使用。准确保存并找回事实是基础，还要考虑什么时候提取、什么时候注入、哪些内容有助于当前互动、哪些内容会产生不合适的影响。

此前的[数据模型](v1-data-model.md)主要处理来源、依据、生命周期和恢复，[检索方案](v1-retrieval-context.md)主要处理候选召回与有界装配。这些基础仍然需要，但不能视为已经完成记忆与人格的交互设计。

第一版先解决记忆，不等于人格只在最后决定措辞。人格的某些变量、既有角色设定和当前用户语境，可能影响注意方向、记忆选择与注入方式。具体由哪条路径承担、变量如何提供，保持开放。

## 2. 用户提出的三条 runtime 路径

| 路径 | 主要意图 | 可能的结果 | 尚未确定 |
| --- | --- | --- | --- |
| 热路径 | 面向当前 request，即时反馈；按当前需求提取、选择并注入记忆 | 本次回答所需的记忆与上下文 | 选择依据、是否需要推理、注入策略及延迟预算 |
| 温路径 | 结合记忆、当前用户语境和有关上下文进行推理 | 推荐记忆条目或话题；不同板块的临时关注度、兴趣点或权重 | 触发时机、人格变量、结果有效期，以及如何影响热路径 |
| 冷路径 | 汇总信息、排查问题、识别并处理矛盾 | 整理后的表示、问题定位与状态调整建议 | 整理范围、自动处理权限、冲突判断与成本控制 |

这是三类职责的初步划分，不代表必须拆成三个进程或服务，也不预设每次请求都依次运行三条路径。温路径不应提前被等同于向量索引维护；它讨论的是与当前交互有关的判断。

温路径的权重是暂时的关注方向，不自动成为记忆的永久重要性、事实可信度或人格本身。是否持久保存这类结果、如何过期或失效，还没有决定；当前不增加相关数据库列。

## 3. 记忆与人格的相互影响

需要一起讨论以下关系：

- 当前请求、用户语境和人格变量，如何影响记忆候选与话题选择。
- 温路径的建议，如何参与热路径的即时选择，而不让过时的兴趣点长期主导回答。
- 记忆进入上下文后，怎样影响角色的判断、表达与后续互动；口头禅和错误先例也可能被强化。
- 冷路径怎样改善后续选择所依据的信息，同时保留必要出处、条件和历史。

“内容好或坏”不宜过早压成一个统一分数。内容可能有真实依据但与当前请求无关；可能相关但不适合此时主动提起；也可能正确记录了角色说过的话，却不适合反复作为行为样本。事实可靠性、当前相关性与交互效果需要分别理解，具体如何组合仍待讨论。

这里保留的是记忆与人格共同设计的方向，不表示第一版已经加入关系成长、情绪状态机或自动人格演化。

## 4. 与已有生命周期和开销设计的关系

三条路径仍需遵守来源授权、更正和遗忘的边界。人格或临时兴趣点不能让失权、已遗忘的内容重新成为可用记忆。

冷路径处理矛盾时，要保留数据模型已有的区别：偏好发生变化、过去记录错误、不同条件下同时成立，以及证据不足以判定。不能把“去掉矛盾”直接实现为只留下时间最新的一句话。

用户明确保存、更正和遗忘仍及时影响后续使用，不等待冷路径整理；具体语义推理和写入入口不在本文重新定义。记忆与话题建议也不自行创建 schedule 或获得执行权限，相关边界见[持久 agent 与调度](persistent-agent-scheduling.md)。

开销需要按路径看：热路径影响即时响应，温路径可能产生额外语境推理费用，冷路径消耗整理与存储维护资源。移到后台不会消除费用，但本轮不确定调用频率、并发、token 限额或抢占方式。原检索文档的数字仅是基础方案的实验起点，不是完整三路径 runtime 的预算。

## 5. 留待后续思考的关系

1. 人格影响选择的变量来自哪里，与用户当前需求如何协调？
2. 温路径何时运行，其结果由谁使用、保留多久、在什么情况下失效？
3. 热路径如何结合直接检索与温路径建议，决定是否注入或主动提及？
4. 冷路径哪些矛盾可以自动处理，哪些需要保留条件、历史或不确定性？
5. 如何同时观察有用性、打扰、先例传播与费用，而不只优化回忆问答分数？

这些是待讨论的问题，不是当前新增的实施计划。[Benchmark 参考](benchmark-references.md)仅提供已有研究的维度和覆盖差距；自建 benchmark 继续后置。
