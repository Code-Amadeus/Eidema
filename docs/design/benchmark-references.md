# Eidema：外部 benchmark 的参考价值与覆盖边界

日期：2026-10-23（Pacific/Auckland）。

状态：资料与设计参考。当前不下载评测数据、不运行评测、不实现评测适配器，也不设计 Eidema 自有 benchmark。本文不规定题量、数据划分、评审模型或通过分数；不把外部作者的成绩写成 Eidema 的能力。

产品语义以[记忆边界](v1-memory-boundaries.md)和[数据模型](v1-data-model.md)为准。外部评测帮助检查遗漏，未来接入可以使用独立适配器，不要求 Eidema 采用某个评测框架的 API 或记忆表示。

## 1. 值得参考的评测

下表最后两列是对 Eidema 的设计判断，不是论文作者对本项目的结论。

| 参考 | 原评测关注什么 | 值得借鉴 | 覆盖边界 |
| --- | --- | --- | --- |
| [LongMemEval](https://github.com/xiaowu0162/LongMemEval/blob/9e0b455f4ef0e2ab8f2e582289761153549043fc/README.md) | 信息提取、跨会话推理、知识更新、时间推理、证据不足时不作答 | 问题时间、历史会话身份、消息级证据标签；区分检索与回答评估 | 问答正确不证明权限隔离、持久删除或后台恢复正确；使用时应注明 cleaned 等数据版本 |
| [MemoryAgentBench](https://arxiv.org/html/2507.05257v4) | 增量交互中的检索、测试时学习、长程理解和选择性遗忘 | 数据逐步进入系统，之后检查更新与冲突处理；避免只看整段历史一次性读入的效果 | selective forgetting 主要测更新事实覆盖旧事实，不验证墓碑、索引残留或旧任务重放 |
| [PrefEval](https://prefeval.github.io/) | 显式和隐式偏好的识别、记忆与后续应用 | 检查偏好能否影响相关回答，关注距离与上下文长度 | 偏好遵循不等于永远注入；研究结果不能直接推出全部显式偏好必须常驻 |
| [PersonaMem](https://github.com/bowen-upenn/PersonaMem/blob/d07e6ade22e85e0e5d562247323a9c3e07553226/README.md) | 用户情况与偏好的动态变化，以及当前场景的个性化回答 | 记录距最近相关信息的距离、无关历史量、问题时可见的历史截止位置 | 这里的 persona 主要是用户画像，不能替代角色人格保真评测；[v2](https://arxiv.org/abs/2512.06688)偏重隐式个性化，也不要求 v1 自动推断用户画像 |
| [LoCoMo](https://github.com/snap-research/locomo) | 长期对话中的问答、事件概述等任务 | 对话与证据关联可作为基础参考 | 需核对数据发布范围、问题类别和计分协议；不同框架的同名总分不直接横比 |
| [LoCoMo-Conv](https://github.com/MiuLab/LoCoMo-Conv/blob/1925e924c36e632283ea91f2212157829f4e0e45/README.md) | 把 LoCoMo 问答改写为自然对话、隐含需求、反事实和组合查询，同时测检索与回复 | 用户不直接询问旧事时，历史是否仍对当前回答有帮助；区分找到证据与正确使用证据 | 仍需另查不该使用记忆的情况；提及旧事实的次数不等于回答质量 |
| [LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2/blob/2cc8c540bdb87fe6761629b585e727e1c4704520/README.md) | 操作轨迹中的静态状态、动态变化、流程经验、环境陷阱和前提判断 | 对未来 Amadeus 的 Work 经验有参考价值；准确率与查询延迟共同衡量 | 不把工作经验学习和多模态轨迹处理提前纳入 Eidema v1，也不以此授予执行权限 |

初版优先借鉴 LongMemEval 的证据结构、LoCoMo-Conv 的对话使用场景，以及 PrefEval／PersonaMem 的偏好应用与变化。LongMemEval-V2 先提供开销与未来工作记忆的参考。

## 2. 三个需要明确区分的概念

### 更新、撤回与遗忘

MemoryAgentBench 的 FactConsolidation 将较旧事实与较新冲突事实按序提供，并要求优先采用后者。它能帮助检查冲突处理，但不等于 Eidema 的删除契约。详见论文的[选择性遗忘定义](https://arxiv.org/html/2507.05257v4#A2.S4)。

Eidema 已有三种不同产品操作：“现在改喝茶”保留过去情况；“之前记错了”撤回错误陈述；“忘掉饮品偏好”排除相关内容及旧来源重放。只检查最终回答是否包含新值，无法证明三种生命周期正确。

### 记住与应用

查问偏好能答对，不保证在相关任务中会使用它；相关任务中使用得当，也不要求每次都复述用户偏好。Host 执行的设置归 Host；Eidema 的回复规则可以先进入候选，经审查后稳定采用，再决定何时提供。不能为了偏好得分把所有 explicit 条目改成常驻上下文，也不能把无条件显式表达当作候选的唯一入口。

### 用户画像与角色人格

PersonaMem 主要关注用户情况与偏好。角色自身的知识边界、口吻漂移、坏先例传播是另一组问题。未来可参考 [TimeChara](https://arxiv.org/abs/2405.18027) 的剧情时间点知识边界；这不扩展 v1 的人格或关系实现范围。

## 3. 对现有数据与可观察性的启发

| 需要保留的信息 | 当前落点 | 用途 |
| --- | --- | --- |
| 来源身份、修订、说话者、范围与依据片段 | sources、evidence、scopes | 判断召回是否来自正确对象、正确版本和获准证据 |
| 问题提出时间与当时可用历史 | 评测／请求侧元数据，结合来源记录时间 | 防止未来信息泄漏；历史问答不能看见后来才出现的更正 |
| 事件发生时间与事实有效期 | memories 的独立时间语义 | 不把过去事件当成过期偏好，也不把更正时间当成事件时间 |
| 状态变化及原因 | memories 生命周期、遗忘规则 | 分开解释过期、撤回、不可用与已遗忘 |
| 检索候选、最终选中身份、使用版本和省略原因 | 有界请求诊断 | 定位问题出在候选检索、有效性过滤、预算装配还是回答模型 |
| 模型／索引配置、尝试用量、阶段耗时和积压 | 维护记录与运行观测 | 避免更换模型、预算或后台工作量后仍把结果归因于同一检索方案 |

标准答案、gold evidence、题型、预期回答和答案选项属于评测侧，不写入生产记忆字段，也不暴露给检索器。问题 id 不能成为选择正确证据的捷径。PersonaMem 的历史截止位置和 LongMemEval 的 has_answer 标签正说明了输入与评估信息需要分开。

诊断优先保存必要的身份、版本、计数与机器原因，采用有界保留期；不能为了调试再留下不会随遗忘清理的正文、prompt 或向量副本。遗忘相关诊断同样遵守内容清理契约。

## 4. 值得保留的指标维度

以下是现有设计需要支持的观测维度，不是一套新的 benchmark 评分规则。

| 层次 | 可参考的指标 | 解释与限制 |
| --- | --- | --- |
| 候选检索 | 有效证据 Recall@k、必要证据组是否齐全 | 多条证据共同必要时，命中其中一条不等于回答依据完整；不同分块粒度的 k 不直接等价 |
| 上下文装配 | 固定 token 预算内的证据覆盖、无关内容占用、预算省略 | 要测真正交给主模型的内容，不能只报排序前候选命中 |
| 回答 | 有依据的正确性、无依据回答、证据不足时恰当不作答 | 字面匹配不适合所有跨语言或自由回答；未来采用的评分方式需要明确 |
| 时间与更新 | 当前值正确性、历史值正确性、撤回内容误用 | 单一“最终新值正确率”会掩盖历史被误删和错误被当成过去事实 |
| 偏好应用 | 相关场景的遵循、条件／临时例外的处理、不相关场景的误用 | 不能靠扩大常驻注入量单独优化遵循率 |
| 前台开销 | 冷／热 p50、p95、超时、注入 tokens | 查询 embedding、检索、验证与装配分阶段；额外主模型工具往返另计 |
| 后台开销 | 实际及未知用量、重试和废弃结果成本、整理量、重复处理 | 不能把费用移到后台后只报告前台便宜；新生成条目多也不等于质量高 |
| 新鲜度与资源 | 提交到词法／语义可召回的时间、索引覆盖、最老积压、RSS、CPU／GPU、磁盘增长 | 延迟很低但索引长期欠账，不能视为完整可用；本地模型也有设备成本 |
| 生命周期正确性 | 越界返回、被排除内容重放、旧操作重复生效 | 属于产品契约，不能与更高问答分数平均后掩盖失败 |

LongMemEval-V2 的官方评分组合准确率与平均记忆查询时间，说明质量与开销可以一起考察；其单一延迟值仍不能替代本地语音场景的尾延迟、后台费用和资源观测。[官方评分说明](https://github.com/xiaowu0162/LongMemEval-V2/blob/2cc8c540bdb87fe6761629b585e727e1c4704520/leaderboard/README.md)

## 5. 这些外部结果不能替 Eidema 证明的场景

下列是已有产品约束的覆盖清单，不是本轮新增的数据集或测试方案：

- 中文问题召回日文原话，且保留说话者归属；同语言成绩不能替代该结果。
- 用户、角色和项目范围隔离，以及共享之后的更正和撤销。
- 删除聊天仍保留显式记忆及独立凭据；自动记忆按剩余依据判断。
- 控制确认复述和未关联提及不会绕过已解析的遗忘范围。
- 遗忘后重启、索引重建、旧 write_key 重送及在途结果返回，都不能恢复被排除内容。
- 可读失效与物理清理分开报告，包括 FTS、向量、缓存、同库保存凭据，以及 Host 窗口和日志投影；外部 provider 独立存储另行说明。
- 合并后替代证据仍有效，旧写入身份仍幂等；部分遗忘不损害同条来源中的无关事实。
- 持续运行时，后台积压、未知费用、断电恢复和前台语音资源竞争可解释。
- 记忆中的错误回答、口头禅或附和是否成为行为先例；角色知识边界和长期人格漂移不能用问答分数替代。
- 记忆提到工作或 schedule，不会自行变成新的行动授权或恢复已取消任务。

“不能替本项目证明”不表示所有外部研究都没有涉及这些问题；这里只说明本文参考的任务与 Eidema 契约之间仍需核实的差距。

## 6. 当前采用方式

当前只维护上述参考映射和观测需求。关于热、温、冷三条运行路径，以及人格如何影响记忆选择，见[运行路径讨论记录](runtime-paths-discussion.md)。设计暂留在初稿阶段，待用户进一步梳理后再收敛；不继续冻结后台参数。已有的[检索流程](v1-retrieval-context.md)和[生命周期例子](v1-data-model.md)保持产品语义，不为榜单调整范围或遗忘定义。

将来决定运行外部评测时，再固定数据修订、回答模型、judge、可见历史、上下文预算、是否读取原文，以及索引建立和后台成本的计入方式。按需使用少量官方样例与完整运行应明确区分，不冒充官方全量成绩。当前没有运行结果，也没有新的评测工程。
